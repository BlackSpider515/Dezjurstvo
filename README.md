# Электронный дневник

SPA для студенческого дневника и кабинета преподавателя: дисциплины, привязанные к группам, журнал, задания с дедлайнами, загрузка работ, просмотр файлов, аннотации «маркером» и три системы оценивания.

Стек: Vite + React 18 + TypeScript + React Router (HashRouter). Бэкенд — Supabase (Postgres, Auth, Storage, Edge Functions). Без Supabase приложение автоматически работает в демо-режиме на `localStorage` + IndexedDB.

В системе могут работать несколько преподавателей. Каждый преподаватель создаёт свои дисциплины и видит только их журналы, задания и работы. Студент видит дисциплины своей группы и переключается между ними.

## Быстрый старт (демо)

```bash
npm install
npm run dev
```

Откройте:

- студент: `http://localhost:5173/#/`
- преподаватель: `http://localhost:5173/#/admin`

Все преподаватели, включая Ксению, регистрируются самостоятельно через вкладку «Регистрация» на `/#/admin`:

- Потапова Ксения Андреевна;
- Пискунов Тимофей Александрович;
- Ерошенко Екатерина Александровна.

Пароль придумывается при регистрации, логин генерируется автоматически и показывается на экране «Кабинет создан» до перехода в журнал. Регистрация доступна только этим трём ФИО. Готовых демо-логинов и паролей больше нет.

По умолчанию в демо-базе есть только группы `211` и `311`. Студентов, дисциплин и заданий нет: студенты появляются после регистрации, преподаватель сначала создаёт дисциплину для группы, затем задания. Демо-данные хранятся только в текущем браузере. Сбросить их можно кнопкой «сбросить» в подвале.

### Как пройти демо-сценарий

1. На `/#/admin` откройте «Регистрация», зарегистрируйте преподавателя (например, Ксению) и запомните сгенерированный логин.
2. Создайте дисциплину, например «Информатика» для группы `211`.
3. Откройте «Профиль» и добавьте аватар, почту, телефон и описание.
4. Добавьте задание с дедлайном или нажмите «Тест-данные», чтобы сразу получить 30 студентов и 50 заданий.
5. Выйдите и зарегистрируйте студента в группе `211` (или войдите под тестовым студентом).
6. Сдайте работу от студента, затем войдите преподавателем и выставьте оценку.
7. После нажатия «Проверено» файл и все его версии удаляются сразу, а оценка и данные о сдаче остаются в журнале.

Если у пользователя несколько дисциплин, после входа открывается выбор дисциплины. Выбранная дисциплина запоминается в браузере.

## Production: Supabase

### 1. Создайте проект

Создайте проект в Supabase и возьмите:

- `Project URL` — в Project Settings → API;
- `anon public key` — там же.

`service_role` в фронтенд не попадает и в репозиторий не коммитится. Он используется только внутри Edge Functions.

### 2. Выполните SQL по порядку

В Supabase SQL Editor выполните миграции из `supabase/migrations/` строго по именам:

1. `20260101000001_schema.sql` — таблицы, индексы, ограничения.
2. `20260101000002_rls.sql` — RLS-политики и helper-функции.
3. `20260101000003_storage.sql` — приватный бакет `submissions`, лимит 50 МБ и политики Storage.
4. `20260101000004_seed.sql` — только группы `211` и `311`. Студентов и заданий там нет.
5. `20260101000005_group_delete.sql` — безопасное удаление пустой группы преподавателем.
6. `20260101000006_neutral_subject.sql` — нейтральное название дисциплины по умолчанию.
7. `20260101000007_submission_hardening.sql` — запрет сдавать без файла, менять студента/задание/оценку и подделывать историю версий.
8. `20260101000008_grade_types_deadlines.sql` — системы оценивания `1–5`, `Зачёт/Незачёт`, `0–100`, полный дедлайн задания и проверка оценки по типу задания.
9. `20260101000009_file_retention.sql` — поля `reviewed_at` и `file_deleted_at` для совместимости. Семидневная задержка больше не используется.
10. `20260101000010_grade_block_with_annotations.sql` — запрет первой оценки, пока у работы есть активные замечания.
11. `20260101000011_disciplines.sql` — дисциплины преподавателей, allowlist, изоляция RLS по дисциплинам, каталог дисциплин и немедленное удаление файлов после подтверждения проверки.
12. `20260101000012_teacher_profiles.sql` — профили преподавателей (аватар, почта, телефон, описание), публичная витрина `teacher_profiles` для студентов и бакет `avatars`.

Если база уже создавалась раньше, новые миграции `5`–`12` нужно выполнить дополнительно. Миграция `11` должна выполняться после `10`, миграция `12` — после `11`.

Что важно в миграции `11`:

- создаётся `public.teacher_allowlist` с тремя разрешёнными ФИО;
- если преподаватель `ksenia@diary.local` уже был создан раньше, он получает ФИО «Потапова Ксения Андреевна» и отметку в allowlist;
- задания получают `discipline_id`, старые задания привязываются к первому преподавателю;
- RLS не даёт преподавателю видеть задания, сдачи и замечания чужой дисциплины;
- студент видит только дисциплины своей группы;
- файлы проверенных работ удаляются сразу после подтверждения проверки.

Таблица `teacher_allowlist` не доступна клиентам `anon`/`authenticated`. Её читает и изменяет только Edge Function через `service_role`.

### 3. Бакет Storage

Миграция создаёт приватный бакет `submissions`:

- public: `false`;
- лимит файла: `52428800` байт (50 МБ);
- путь: `{student_id}/{assignment_id}/{uuid}.{ext}`;
- доступ — только владелец работы или преподаватель, владеющий дисциплиной;
- просмотр — через signed URL.

Если бакет создаётся вручную, задайте те же параметры и выполните политики из `20260101000003_storage.sql` и `20260101000011_disciplines.sql`.

Миграция `12` дополнительно создаёт публичный бакет `avatars` (2 МБ, JPG/PNG/WebP). Путь: `{teacher_id}/{uuid}.jpg`. Читать аватары могут все, загружать и удалять — только сам преподаватель.

### 4. Edge Functions

Задеплойте обе функции:

```bash
supabase functions deploy register --no-verify-jwt
supabase functions deploy register-teacher --no-verify-jwt
```

- `register` создаёт студента (`auth.users` + `profiles`) и возвращает логин/пароль один раз.
- `register-teacher` создаёт преподавателя только для ФИО из `teacher_allowlist`, генерирует логин и возвращает его.

Секреты `SUPABASE_URL` и `SUPABASE_SERVICE_ROLE_KEY` Supabase передаёт функциям автоматически. Ключ `service_role` нельзя добавлять в `.env` фронтенда или в GitHub Variables/Secrets, которые попадают в клиентскую сборку.

### 5. Преподаватели

В production все три преподавателя, включая Ксению, регистрируются самостоятельно на `/#/admin` → «Регистрация»:

- ФИО должно точно совпадать с записью в `teacher_allowlist`: `Потапова Ксения Андреевна`, `Пискунов Тимофей Александрович` или `Ерошенко Екатерина Александровна`;
- пароль — минимум 8 символов;
- после регистрации показывается сгенерированный логин, затем открывается журнал.

Готовых логинов и паролей в репозитории нет. Ксения не создаётся заранее: при первом входе она регистрируется так же, как остальные.

`supabase/make_admin.sql` — только запасной способ восстановления доступа. Он предполагает, что пользователь уже создан в Dashboard → Authentication → Users, и закрепляет его профиль и ФИО в allowlist. Если выполнить этот скрипт для Ксении заранее, самостоятельная регистрация для неё станет недоступна.

Чтобы добавить нового преподавателя, добавьте его ФИО в `teacher_allowlist` через SQL Editor (не через фронтенд), затем он сможет зарегистрироваться сам. Удаление записи из allowlist не удаляет уже созданный аккаунт.

Пароль преподавателя хранится только в Supabase Auth. В коде приложения его нет.

### 6. Профиль преподавателя

Преподаватель открывает «Профиль» в верхнем меню и может:

- загрузить аватар (JPG/PNG/WebP, после подготовки — до 512 px и 2 МБ);
- указать контактную почту, телефон и описание.

Студент открывает профиль преподавателя по ссылке с именем преподавателя в журнале, в списке дисциплин или в заданиях. Студенту доступны только ФИО, аватар, почта, телефон и описание — без служебных данных аккаунта.

Аватары хранятся в публичном бакете `avatars`: студент должен видеть фото без signed URL. Загружать, менять и удалять файлы может только сам преподаватель; это проверяют RLS-политики Storage. Контактные поля также защищены RLS и колоночными правами.

### 7. Переменные окружения

Скопируйте `.env.example` в `.env`:

```env
VITE_SUPABASE_URL=https://YOUR-PROJECT.supabase.co
VITE_SUPABASE_ANON_KEY=YOUR-ANON-KEY
VITE_DEMO_MODE=false
VITE_SUBJECT_NAME=Учебная дисциплина
VITE_ENABLE_EDITING=false
VITE_ONLYOFFICE_URL=
```

Файл `.env` уже добавлен в `.gitignore`.

Если `VITE_SUPABASE_URL`/`VITE_SUPABASE_ANON_KEY` не заданы или включён `VITE_DEMO_MODE=true`, приложение работает в демо-режиме.

### 8. GitHub Pages

В репозитории есть workflow `.github/workflows/deploy.yml`. Он собирает проект и публикует `dist`.

1. Создайте GitHub-репозиторий и запушьте проект в ветку `main`.
2. В Settings → Pages выберите источник **GitHub Actions**.
3. В Settings → Secrets and variables → Actions добавьте:
   - Variables: `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`, при необходимости `VITE_SUBJECT_NAME`, `VITE_ENABLE_EDITING`, `VITE_ONLYOFFICE_URL`;
   - либо те же значения как Secrets, если предпочитаете их скрывать. Workflow читает сначала Variables, затем Secrets.
4. Запустите workflow `Deploy to GitHub Pages` или сделайте push в `main`.

`VITE_BASE` workflow выставляет автоматически как `/<имя-репозитория>/`. Приложение использует HashRouter, поэтому маршруты вида `/#/admin` работают на GitHub Pages без дополнительной настройки rewrite.

Не забудьте после деплоя фронтенда задеплоить миграции и обе Edge Functions в Supabase.

## Правила и ограничения

- Студент видит только свою группу и свои работы; в журнале его строка подсвечена.
- Преподаватель видит только свои дисциплины, их журналы, задания, работы и замечания.
- Дисциплина создаётся преподавателем и привязывается к группе. Название дисциплины уникально в рамках группы.
- Преподаватель может удалить свою дисциплину из списка дисциплин. Вместе с ней каскадно удаляются её задания, сдачи, замечания и файлы из Storage.
- Если у пользователя несколько дисциплин, после входа показывается выбор. Выбор запоминается для этого профиля.
- В журнале преподавателя есть кнопка «Тест-данные»: она добавляет 30 демонстрационных студентов в группу дисциплины и 50 заданий. В Supabase студенты создаются как реальные аккаунты через Edge Function `register`, поэтому используйте кнопку только для проверки.
- Регистрация студента: ФИО + группа. Дубликат «ФИО + группа» запрещён.
- Логин студента генерируется один раз, пароль показывается один раз. Технический email: `login@diary.local`.
- Задания по умолчанию не создаются. Их добавляет преподаватель в своей дисциплине.
- Группы по умолчанию: `211` и `311`. Преподаватель может добавлять и переименовывать группы.
- Удалить можно только группу без студентов. Если в группе есть студенты, интерфейс и SQL-функция `delete_group` не дадут её удалить.
- Для каждого задания преподаватель выбирает систему оценивания: `1–5`, `Зачёт/Незачёт` или `0–100`. После выставления первой оценки систему задания менять нельзя.
- Дедлайн задания задаётся датой и временем. Если дедлайн прошёл, а работа не сдана, в журнале и в карточке задания показывается красное «Срочно сдать!».
- После выставления оценки работа блокируется от замены файла.
- При выставлении оценки преподаватель подтверждает: «Вы точно проверили задание полностью?». После «Проверено» текущий файл и все прошлые версии сразу удаляются из Storage. Оценка, замечания, имя и размер файла, данные о сдаче сохраняются.
- Если удалить файл сразу не удалось (например, пропала сеть), при следующем открытии преподавателем разделов «Журнал» или «Задания» срабатывает резервная очистка оценённых работ.
- Комментарии «маркера» хранятся в БД; писать их может только преподаватель, студент видит их в режиме чтения.
- Если у неоценённой сданной работы есть активные замечания, в журнале появляется красное «Исправить». Студент видит этот статус только в своей строке; преподаватель — у всех студентов.
- Пока работа не оценена и у неё есть активные замечания, первую оценку ставить нельзя. Активными считаются замечания, оставленные после последней загруженной версии. После загрузки новой версии статус «Исправить» снимается автоматически.
- Если оценка уже выставлена, в журнале показывается она, а не «Исправить». Преподаватель может изменить или снять такую оценку.
- Безопасность обеспечивается RLS и политиками Storage, а не только интерфейсом.

## Файлы

Разрешены: `doc`, `docx`, `xls`, `xlsx`, `ppt`, `pptx`, `pdf`, `txt`, `zip`, `rar`, `mp4`.

- Максимальный размер: 50 МБ.
- Файл проверенной работы и все его прошлые версии удаляются сразу после подтверждения проверки.
- Резервная очистка оценённых файлов запускается при открытии преподавателем разделов «Журнал» или «Задания»: у статического GitHub Pages нет собственного планировщика.
- Удаляются текущий файл и все версии; запись работы, оценка, замечания, имя и размер файла остаются.
- Файлы приватные, выдаются по signed URL.
- PDF — PDF.js; DOCX — `docx-preview`; XLSX — SheetJS; PPTX — превью/скачивание; TXT — чтение; MP4 — встроенный плеер; ZIP — список файлов.
- Старые `.doc`, `.xls`, `.ppt` и `.rar` не рендерятся в браузере и предлагаются для скачивания.
- Аннотации: PDF — страница + прямоугольник; DOCX/TXT — диапазон текста. Комментарий хранится отдельно от файла.

Полноценное редактирование Word в браузере с сохранением всех стилей, колонтитулов и режима правок требует серверного движка (например, ONLYOFFICE Docs). Текущий просмотрщик ориентирован на корректное отображение документа, а не на его редактирование.

## Демо-режим и сон Supabase

Бесплатный проект Supabase может засыпать после простоя. При первом запросе после сна возможна задержка или ошибка сети — повторите действие через 10–30 секунд. Для учебной нагрузки этого достаточно; при постоянной работе нужен платный план или внешний пингер.

Демо-режим не требует сети и не отправляет данные на сервер. Очистка данных браузера или кнопка «сбросить» возвращает состояние по умолчанию: группы `211`/`311`, без студентов, дисциплин и заданий. Чтобы посмотреть заполненный журнал, создайте дисциплину и нажмите «Тест-данные» — в демо-режиме появятся 30 студентов и 50 заданий.
